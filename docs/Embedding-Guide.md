# Embedding guide

How an application ties the engine in. The shape is always the same:

1. create an `Interp`, passing a **host** (your surroundings) and options,
2. add your own commands and functions,
3. feed it input (script text, lines from the outside),
4. react to what it asks of you (echoed text, lines to send, events).

## The host

An interpreter talks to the outside world through a `Host`, which has two
methods:

```go
type Host interface {
    Echo(text string)                  // show text to the user
    Send(world, text string) bool      // send a line to a connection
}
```

For a quick start use the built-ins:

```go
gtfparser.Console(os.Stdout)     // echoes to a writer; sends print as "-> line"
gtfparser.HostFuncs{             // adapt two functions
    OnEcho: func(t string) { ui.Append(t) },
    OnSend: func(world, t string) bool { return conns.Write(world, t) },
}
```

or implement the interface on your own type. `world` is a name for "which
connection"; the empty string means the current one. If your program has only
one place to send to, ignore it.

### Optional capabilities

Everything else a client might provide is an **optional interface** that the
host implements when it can. The engine checks for them with a type assertion;
if one is missing, the commands that need it say so
(`% /connect: not supported by this client`) instead of pretending.

| Interface | Provides | Used by |
|---|---|---|
| `WorldHost` | connect, disconnect, foreground world, connection state | `/connect`, `/dc`, `/fg`, `is_connected()`... |
| `Notifier` | receive engine events (`beep`, `status`, `limit`, `restrict`...) | anything the user should see or hear |
| `KeyHost` | terminal key sequences | `keycode()` |
| `TermHost` | screen size | `columns()`, `lines()` |
| `HelpHost` | show a help topic | `/help` |

```go
type myHost struct{ /* ... */ }
func (h *myHost) Echo(t string)                {...}
func (h *myHost) Send(w, t string) bool        {...}
func (h *myHost) Notify(e gtfparser.Event)     { if e.Kind == "beep" { h.bell() } } // opt in to events
func (h *myHost) Size() (cols, lines int)      { return 120, 40 }                    // opt in to size
```

Implement exactly what makes sense for your program, nothing more.

## Creating the interpreter

```go
in := gtfparser.New(host,
    gtfparser.WithLibDirs(libDir),                       // where /load finds files
    gtfparser.WithLimits(gtfparser.Limits{...}),         // resource ceilings
    gtfparser.WithPolicy(rules),                         // your veto over privileged ops
    gtfparser.WithRestriction(gtfparser.RestrictShell),  // tf's own /restrict
    gtfparser.WithoutEnvironment(),                      // don't import os env as variables
)
```

By default the process environment is imported as script variables (`%{HOME}`),
as tf does. A server hosting other people's scripts will want
`WithoutEnvironment()`.

## Feeding it input

| Method | Use it for | Semantics |
|---|---|---|
| `in.Run(text)` | commands typed or generated by your program | like a macro body: full substitution, `%;` separates commands |
| `in.Exec(line)` | a line from a script file | no substitution until a macro runs; `%;` does not split except in `/if`/`/while` |
| `in.LoadFile(path)` | a script file | joins `\` continuations, skips `;` comments |
| `in.Eval(expr)` | an expression for its value | returns a `Value` (`.String()`, `.Int()`, `.Float()`, `.Truth()`) |
| `in.ProcessLine(line)` | a line that arrived from the world | runs matching triggers |
| `in.Process(line, live)` / `in.ProcessText(LineInput{...})` | the same, wanting to know what happened | returns what matched, the attributes to display, gag/no-log flags (see [triggers-hooks](engine/triggers-hooks.md)); `live` false only matches |
| `in.FireHook(event, args)` | something happened in the client (connect, send, ...) | runs the hooked macros, returns the ones that ran (see [hooks](engine/hooks.md)) |
| `in.RunDue()` / `NextDue()` | timers (`/repeat`, `/quote`) | or let a `Runner` do it |

The difference between `Run` and `Exec` is the single most important thing to
know about tf; see [Evaluation model](language/Evaluation-Model.md).

## Reacting to the engine

Scripts reach your program through the host:

- `/echo`, `/send` and friends call `Echo` and `Send`;
- state changes (`/beep`, `/localecho`, `/restrict`, status line, ...) arrive as
  `Notify(Event)` if you implement `Notifier`;
- your own commands and functions run your own Go code
  ([Extending the engine](Extending-the-Engine.md)).

## Reading and writing variables

```go
in.SetVar("player", "Zaphod")           // script sees %{player} and `player` in expressions
name := in.Var("player")                // read anything a script set
```

Variables are strings in Go terms; scripts see integer, decimal, float or
string depending on how they were set (see [Expressions](language/Expressions.md)).

## One goroutine at a time

An `Interp` is not safe for concurrent use. If sockets, a UI loop and timers
all need it, wrap it in a `Runner`
([Concurrency and performance](Concurrency-and-Performance.md)).

## A complete small example

A line-driven bot that reacts to text and answers back:

```go
host := gtfparser.HostFuncs{
    OnEcho: func(t string) { log.Println("[bot]", t) },
    OnSend: func(_, t string) bool { _, err := conn.Write([]byte(t + "\r\n")); return err == nil },
}
in := gtfparser.New(host, gtfparser.WithoutEnvironment())
in.LoadFile("bot.tf")                       // triggers and macros written by the user

scanner := bufio.NewScanner(conn)
for scanner.Scan() {
    in.ProcessLine(scanner.Text())          // everything else happens in bot.tf
}
```

with `bot.tf`:

```tf-noverify
; answer greetings, heal when hurt
/def -t'* says, "hello"' greet = say Hello, %1!
/def -mregexp -t'HP: (\d+)/(\d+)' lowhp = /if ({P1} < {P2} / 3) quaff potion%; /endif
```
